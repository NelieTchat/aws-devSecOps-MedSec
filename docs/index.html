Overview

What this project demonstrates

MedSec is a DevSecOps reference project for a healthcare portal, built to show how to ship secure infrastructure in a regulated environment — where security is a pipeline gate, not an afterthought. The architecture follows FedRAMP-aligned principles: private networking, least-privilege IAM, encrypted storage, and automated compliance checks at every stage of delivery.

  • Zero public exposure — private VPC with VPC endpoints for ECR, SSM, Secrets Manager, and CloudWatch. No internet gateway, no NAT.
  • No long-lived credentials — GitHub OIDC authenticates CI/CD pipelines with branch-scoped IAM roles. Credentials exist only for the duration of a workflow run.
  • Security scanning on every push — Checkov scans Terraform for IaC misconfigurations, Trivy scans container images for CVEs, before any artifact reaches ECR.
  • Modular, environment-aware IaC — Terraform split across network, ECR, and IAM modules with separate dev/staging/prod env configs. One codebase, consistent deployments.
  • Observable by design — tagging strategy enforced across all resources (Project, Env, Owner) for cost allocation, audit trails, and incident response.
Architecture

Infrastructure layers

The architecture is structured in three independent Terraform modules, each ownable and deployable separately.

[NET]

Network layer

Private VPC in us-west-2 with isolated subnets and VPC endpoints. No IGW, no NAT — traffic stays inside AWS backbone.

[ECR]

Container registry

Amazon ECR with immutable image tags, scan-on-push, and lifecycle policies to cap storage. Images versioned as :env-sha.

[IAM]

Identity & access

GitHub OIDC role scoped to repository and branch. No static AWS keys anywhere — not in secrets, not in env vars.

[APP]

Application

Containerized Node.js portal with /health endpoint. Designed for ECS Fargate deployment behind ALB + WAF.

[CI]

CI/CD pipeline

GitHub Actions: authenticate via OIDC → build Docker image → run Trivy scan → push to ECR as :dev-sha.

[OPS]

Observability

Prometheus + Grafana configs in progress. All resources tagged for CloudWatch metric filtering and cost attribution.

CI/CD Pipeline

Every commit goes through this

# .github/workflows/dev-ci.yml — triggered on push to dev branch on: push: branches: [dev] jobs: build-scan-push: permissions: id-token: write # required for OIDC contents: read steps: - name: Authenticate via OIDC (no static keys) uses: aws-actions/configure-aws-credentials@v4 with: role-to-assume: ${{ secrets.CI_ROLE_ARN }} aws-region: us-west-2 - name: Build Docker image run: docker build -t medsec-portal:${{ github.sha }} ./app - name: Trivy scan — fail on CRITICAL CVEs uses: aquasecurity/trivy-action@master with: image-ref: medsec-portal:${{ github.sha }} exit-code: '1' severity: CRITICAL - name: Push to ECR (only if scan passes) run: docker push $ECR_REPO:dev-${{ github.sha }}
Security Controls

Security by design, not by checkbox

Every control here maps to a real attack vector, not a compliance form field.

// OIDC authentication

GitHub Actions authenticates to AWS via federated OIDC. IAM role scoped to repo + branch. Zero static credentials in any config file or secret store.

// Private networking

All compute runs in private subnets with no internet gateway. VPC endpoints route traffic to AWS services without leaving the VPC.

// IaC scanning (Checkov)

Checkov runs on every Terraform change. Misconfigured S3 buckets, open security groups, and missing encryption trigger pipeline failures before apply.

// Container scanning (Trivy)

Trivy scans every image for known CVEs before it reaches ECR. CRITICAL severity findings block the push — no exceptions.

// Immutable image tags

ECR configured with image tag immutability. Once :dev-sha is pushed, it cannot be overwritten — every deployment is auditable and reproducible.

// Least-privilege IAM

CI role permits only ECR push and CloudWatch logging. No wildcard actions, no cross-account trust. Principle of least privilege enforced in Terraform.
